### 2. 수면 단계 4단계 전환 (합의안 5-1 #1, 5-2 #2 / 1순위 md #4)
`SleepStage`: `WAKE/N1/N2/N3/REM` → `WAKE/LIGHT/DEEP/REM` (+UNKNOWN)

| enum | code | 표시(label) |
|---|---|---|
| WAKE | 0 | AWAKE |
| LIGHT | 1 | LIGHT |
| DEEP | 2 | DEEP |
| REM | 3 | REM |
| UNKNOWN | -1 | UNKNOWN |

- enum 이름 `WAKE`는 채윤 코드 호환을 위해 유지, 화면·파일 표기는 `AWAKE`.
- `code`(0~3)는 **워치 전용 번호**. PSG 평가코드의 stage_label(0=W,1=N1,…)과 다른 체계.

영향 파일:
- `HealthModels.kt` — enum 정의, `DISPLAY_ORDER`(AWAKE/REM/LIGHT/DEEP)
- `EpochAggregator.kt` — 코드 범위 -1~3, 수면 시간은 `isSleep` 기준
- `SleepStageChart.kt` — 세로축 AWAKE/REM/LIGHT/DEEP, 색
- `FakeDataSource.kt` — 가상 데이터도 4단계 (N1+N2→LIGHT, N3→DEEP)
- `MainActivity.kt` — 단계 분포 표시

## 2026-09-25 · 시간대 수정 (합의안 4절 "시간대 오류: 소빈")

### 문제 두 가지
1. **파싱:** 삼성헬스 CSV 의 시각은 **UTC** 인데 `CsvFileSource` 가 KST 로 읽음 → 모든 시각이 9시간 이르게 잡힘
   - 근거: 혜지 데이터의 긴 수면이 원본 기준 18~21시 시작·2~3시 종료(UTC 로 읽어야 KST 03~06시 취침·11~12시 기상),
     삼성헬스 export 분석 자료 "time based fields are UTC time, the time offset is in a separate column"
   - ⚠ 혜지에게 9/14 실제 취침 시각 확인 요청 필요. 다르면 `SAMSUNG_TIMES_ARE_UTC = false` 한 줄로 되돌림
2. **표시:** 화면·night 계산이 **기기 시간대**를 써서 에뮬레이터(UTC)에서 9시간 다르게 보임. 모델은 Asia/Seoul 고정이라 서로 어긋남

### 수정
| 파일 | 내용 |
|---|---|
| `HealthModels.kt` | 앱 기준 시간대 `APP_ZONE = Asia/Seoul` 추가, `TimeFmt` 전부 이 시간대로 표시 |
| `EpochAggregator.kt` | night(정오 기준) 계산을 `APP_ZONE` 으로 |
| `FakeDataSource.kt` | 가상 데이터 자정 계산도 `APP_ZONE` 으로 |
| `AnalysisDisplay.kt` | 분석 화면 시각 표시를 `APP_ZONE` 으로 |
| `CsvFileSource.kt` | **[통합 수정]** 원본 시각을 UTC 로 파싱 (`SAMSUNG_TIMES_ARE_UTC`) |

### 검증 (기기 시간대를 일부러 UTC 로 두고 실행)
